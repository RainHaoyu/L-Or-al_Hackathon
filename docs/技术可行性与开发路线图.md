## 一、赛题理解与方案定位

### 1.1 赛题解读

赛道三命题："AI 能让美属于每一个人吗？"——美不应被感官、身体或时空局限，倡导"AI 向善"，用有温度的技术减少隔阂。任务细则鼓励多模态 AI Agent、软硬件、Physical AI 等前沿技术，**最终产出要求有可演示的软硬件系统尤佳**。

宏观规划（策划案 V1 + 方案评价与优化）已确定的口径：

| 决策项 | 结论 |
|---|---|
| 产品定位 | "万象 Aura"：香味可视化 + 致敏原智能预警双核驱动，让失嗅/敏感肌/孕妇/鼻炎人群平等享受香水之美 |
| 功能取舍 | **保留**：致敏预警（强差异化核心，"有些人不是不想用香水，而是不敢用"）、香味可视化（全方案最有价值亮点）、瓶身识别三通道+基础推荐；**砍掉**：面部风格识别（无科学依据）、场景评分（门槛低）、门店硬件模块（周期长） |
| 演示形态 | 纯软件 Web/H5（黑客松内可完成完整可交互 Demo），硬件方案否决 |
| 评委关注 | "实体交互 + AI"、直观可视化体验、IFRA 标准专业性、按人群差异化建议 |
| 差异化红线 | 避开 Myrissi™ 式"已知香水可视化"，主打**未知香水识别 → 分析 → 可视化 + 失嗅人群关怀** |

## 二、QRA2 模型（替代 v3 报告 1.1.1 节的 QRA v1）

> **替换声明**：v3 报告 1.1.1 节的 QRA 量化风险评估模型（Api et al. 2008，确定性 AEL/CEL 二值判定）自本文档起整体替换为 **QRA2 模型**（基于 IFRA/RIFM QRA 2.0 概率化聚合暴露思路的自研简化实现）。v3 报告其余部分（氧化模型 1.1.2、人群分级 1.1.3、可视化 1.2 等）继续有效，其中人群分级与氧化模型并入 QRA2 判定流程。

### 2.1 被替换的 QRA v1（保留作为基线闸门）

- 核心公式：`AEL = NESIL ÷ SAF`；判定：`AEL ÷ CEL ≥ 1 → 可接受；< 1 → 不可接受`
- 算例（v3 报告原文）：柠檬烯 5%，单次 0.5 mg/cm² × 100 cm² × 日 2 次 × 吸收率 100% → CEL = 5.0 μg/cm²/day；NESIL=10000、SAF=100 → AEL=100；比值 20.0 → 低风险

**v1 的缺陷**（替换动机）：
1. SCCP（欧盟消费品科学委员会）明确批评："该方法尚未经验证……无法确信 QRA 所确定的暴露水平对消费者是安全的"；
2. 点估计无法表达暴露参数的不确定性（用量/面积/频率/浓度/吸收率个体差异巨大）；
3. 二值判定（可接受/不可接受）无过渡带，无法支撑"红/黄/绿"三级的稳健分级；
4. 单产品孤立的暴露计算忽略了消费者同时使用多种留香产品（香水+身体乳+洗发水）的**聚合暴露**——这正是 IFRA 推出 QRA 2.0 的核心理念。

### 2.2 QRA2 模型完整定义

**判定流水线（七步）**：

**Step 1 闸门基线（继承 QRA1）**：`AEL = NESIL ÷ SAF`

| 参数 | 含义 | 数据来源 |
|---|---|---|
| NESIL | 无预期致敏诱导水平 | LLNA 试验 EC3 值或人体 HRIPT/HRPT 数据（RIFM 安全评估报告） |
| SAF | 致敏评估因子 | 种间差异×10 × 个体差异×10 × 场景×1-10，总范围 10-1000 |

**Step 2 CEL 概率化**（QRA2 核心改造）：五参数由标量升级为概率分布

| 暴露参数 | 分布假设 | 依据 |
|---|---|---|
| 单次产品用量 | LogNormal，变异系数 CV=0.4 | 用量个体差异呈右偏分布 |
| 涂抹面积 | Triangular(50, 100, 200) cm² | 手腕局部 → 全身区间 |
| 日使用频率 | 离散分布 {1次:0.5, 2次:0.35, 3次:0.15} | 消费者使用习惯调研 |
| 成分浓度 | Uniform(0.8c₀, 1.2c₀) | 批次间浓度波动 ±20% |
| 皮肤吸收率 | Beta(20, 2)（均值≈0.91，右偏） | 保守估计接近全吸收 |

抽样方法：**拉丁超立方抽样（LHS），N=10,000，固定随机种子**——保证任何人在任何时候重算结果完全一致（路演可复算性，评委可验证）。

**Step 3 聚合暴露**：`CEL_total = Σ(CEL_i × w_i)`，i 遍历同场景留香产品（身体乳 w=0.8、洗发水 w=0.3，权重进 config 可配置），体现 QRA 2.0 "多产品聚合暴露"理念。

**Step 4 分位判定**：输出 CEL 的 **P50 / P90 / P99** 三个分位数，判定规则：
- 健康成人：用 **P90** 分位线（容许 10% 高暴露人群风险）
- 脆弱人群（敏感肌/孕妇/失嗅/鼻炎）：自动升至 **P99** 分位线（更保守）
- P99 分位下 `AEL ÷ CEL[P99] < 1` → 红灯；P90/P99 之间 → 黄灯；均安全 → 绿灯

**Step 5 四道闸门取最严**（`strictest()`，同级按 禁用 > IFRA > 临床 > QRA2 优先）：

| 闸门 | 判据 | 红灯条件 | 黄灯条件 |
|---|---|---|---|
| ① QRA2 分位 | AEL ÷ CEL[policy] ÷ T_pop | < 1（policy=人群分位线） | 接近 1 的过渡带 |
| ② 临床阈值 | 人体 NOEL/LOEL（HRIPT 数据） | 暴露 > 人体 NOEL | 暴露 > NOEL 的 80% |
| ③ IFRA 限量 | IFRA 第 51 版 Cat 4（香水类） | 浓度 ≥ 限值 | 浓度 ≥ 限值 80% |
| ④ 禁用清单 | EU Annex II / 生殖毒性（如 Lilial 已禁、HICC） | 命中即红 | — |

**Step 6 人群差异化**：`T_pop = α × β`（阈值收缩系数）

| 人群 | α（敏感系数） | 附加检查 | β |
|---|---|---|---|
| 健康成人 | 1.0 | 无 | 1.0 |
| 敏感肌 | 3.0 | 交叉反应检查（同族致敏原） | 1.0-1.5 |
| 孕妇 | 1.0 | 生殖毒性成分直判红（邻苯二甲酸酯、Lilial 等） | 1.0 |
| 过敏性鼻炎 | 1.2 | 高挥发性醛类（柠檬醛、肉桂醛）呼吸道刺激标注 | 1.0 |
| 失嗅人群 | 1.0 | **氧化等级并入综合判定**（无法靠嗅觉发现变质） | 1.0 |

**Step 7 氧化动态风险**（v3 报告 1.1.2 并入）：`D = 1 − exp(−k_eff · t)`，其中 `k_eff = k_ox · Q10^((T−T_ref)/10) · (1 + L)`
- t=开封天数，T=储存温度，L=光照暴露(0-1)，k_ox：柠檬烯 0.01-0.05/day、芳樟醇 0.005-0.03/day
- 分级：D<0.2 低（正常使用）｜0.2≤D<0.5 中（敏感肌/孕妇减用）｜D≥0.5 高（建议不再使用）
- 对失嗅人群意义：正常人靠"变味"察觉氧化变质，失嗅者无此通道 → D 值是**嗅觉替代预警**

### 2.3 数据诚实性三原则（QRA2 的工程伦理）

1. **evidence 分级**：文献级 NESIL（RIFM/人体数据）标 `documented`；演示估计值叠加 **×3 保守惩罚**后标 `indicative`；两者在前端明示；
2. **无数据不静默**：某成分查不到 NESIL/限值时，绝不悄悄跳过，而是显式标注"数据不足"，整体结果至少给黄灯（**数据不足 ≠ 安全**）；
3. **免责与口径**：输出页固定展示"本结果为基于公开文献的估算，不构成医学建议；QRA 方法本身仍在国际验证中，本系统采用 QRA2 + 临床阈值 + IFRA 限量三源交叉校验降低单一模型误差"。

### 2.4 v1 → QRA2 差异对照表

| 维度 | QRA v1（v3 报告原方案） | QRA2（本方案） |
|---|---|---|
| CEL 处理 | 单点估计（5 个标量相乘） | 五参数概率分布 + LHS 蒙特卡洛 N=10000 |
| 输出 | AEL/CEL 单一比值 | P50/P90/P99 分位谱 + 各成分余量分布 |
| 判定 | 二值（≥1 可接受） | 四道闸门取最严 → 红/黄/绿三级 |
| 聚合暴露 | 无（单产品孤立计算） | CEL_total = Σ(CEL×w)，多产品加权 |
| 人群差异 | R_final = R_base × α × β（乘在风险值上） | 分位线收紧（P90→P99）+ T_pop 系数 + 禁用直判 |
| 验证性缺陷应对 | "双轨交叉校验"仅口头提及 | 临床 NOEL 闸门实装 + evidence 分级 + 免责声明 |
| 可复算性 | 手算即可但无随机性表述 | 固定随机种子，任何人重算结果一致 |
| 数据缺失 | "标注数据不足" | 显式黄灯 + 前端明示 + admin 热更新补数据 |

### 2.5 黄金算例（验收基准）

沿用 v3 算例参数（柠檬烯 5%、NESIL=10000、SAF=100 → AEL=100 μg/cm²/day）：

- **点估计复现**（校验实现正确性）：CEL = 0.05 × 0.5 × 100 × 2 × 1.0 = **5.0**，AEL/CEL = **20.0** → 绿灯（与 v3 报告一致）；
- **概率化判定**（展示 QRA2 价值）：同一成分分布下 CEL 的 P99 ≈ 13-14 μg/cm²/day；若某成分 NESIL 较低使 AEL=10，则 P99 余量 = 10÷13 < 1 → **红灯**——点估计看起来安全（比值可能仍 >1 的边缘成分），脆弱人群 P99 分位线会暴露真实风险，这正是 v1 做不到的；
- **测试要求**：黄金算例写入自动化测试，点估计精确相等、P50/P90/P99 宽容差但保序、固定种子复算一致、浓度线性、敏感肌/孕期/失嗅路径各自触发预期灯色。

| 4 | 致敏原匹配 | 规则引擎（INCI/CAS/别名/模糊匹配） | ★★★★★ | **可行** | 本质是知识库查询，确定性强；难点仅在同义词表覆盖 |
| 5 | **QRA2 计算** | 公式 + scipy 蒙特卡洛 | ★★★★☆ | **可行，数据是瓶颈** | 计算本身无难度；NESIL/SAF/IFRA 限值/浓度四类参数的文献获取决定结果可信度（见 3.2） |
| 6 | 香味可视化 | ECharts + Canvas/Lottie | ★★★★☆ | **可行，需预研** | 图表与粒子技术成熟；香调→视觉映射规则库需要设计打磨（有 Gilbert 1996/Spence 2020 学术支撑） |
| 7 | LLM 通感文案 | qwen-max 文本生成 | ★★★★☆ | **可行** | 通感化描述是 LLM 强项；需 Prompt 分三种 VisionMode 外置管理 |
| 8 | 氧化风险估算 | 规则计算 | ★★★☆☆ | **可行，需标注局限** | 概率性提示而非精确检测，必须标注"估算"；对失嗅人群是差异化亮点 |
| 9 | 肤香匹配推荐 | 深度学习/推荐系统 | ★☆☆☆☆ | **不可行，仅概念** | 需大规模用户反馈与嗅觉数字化硬件（v3 报告自评 ★1）——Demo 中只做概念展示页 |

**总评：技术栈整体可行。** 8/9 模块可行（其中 3 个"可行需调试/预研"），唯一不可行的肤香匹配按 v3 报告原意降级为概念展示。系统没有需要自研训练模型的部分——全部依赖成熟 API 与确定性计算，这是 48 小时时间盒内最稳的架构。

### 3.2 v3 全阿里云技术栈的轻重取舍

v3 报告 2.1 节规划了全阿里云方案（函数计算 FC + RDS PostgreSQL + Redis Tair + API 网关 + OSS/CDN + SLS）。逐项判断：

| v3 组件 | 黑客松 48h 内 | 生产化阶段 | 结论 |
|---|---|---|---|
| qwen-vl-max / qwen-max（百炼） | ✅ 必须 | ✅ | **采纳**——AI 能力核心，OpenAI 兼容模式接入快 |
| 函数计算 FC 3.0 | ⚠️ 过重 | ✅ | 开发期本地 FastAPI 直跑；上云作为部署阶段可选步骤 |
| RDS PostgreSQL | ⚠️ 过重 | ✅ | 开发期 seed JSON 文件 + 内存仓库（数据量 71 条致敏原+几百香水，JSON 完全够）；生产化再迁 JSONB |
| Redis Tair 缓存 | ❌ 不需要 | ✅ | Demo 并发量极小；生产化再上 |
| API 网关 / SLS / OSS / CDN | ❌ 不需要 | ✅ | 同上 |

**结论**：AI 调用层按 v3 全盘采纳（统一阿里云百炼，国内合规、中文强、Function Call 支持）；**基础设施层在开发期用"本地 FastAPI + seed JSON"轻量等价替代**，v3 云栈整体降级为"生产化部署阶段"的路线图（第 5.8 节），避免 48 小时耗在运维上。这样既保留 v3 报告的云端架构叙事（答辩可讲），又不被它拖慢开发。

### 3.3 《技术分析2》风险警示的落点

1. **"最大的问题还是数据来源"** → 缓解：致敏原知识库以 IFRA 第 51 版 + EU 2023/1545（81 条新规）+ RIFM 文献为骨架，配 evidence 分级与"数据不足黄灯"兜底；香水成分库优先欧莱雅旗下品牌（YSL/兰蔻/科颜氏/Margiela 等官网公开成分表）；
2. **成分保密/缺失** → 缓解：识别置信度 <0.7 强制手动确认；四通道全部失败的兜底是"手动输入 INCI 清单"通道，保证核心链路（成分→QRA2→报告）永远可演示；
3. **静态 vs 动态工作量** → 缓解：先做"库内已知香水"静态链路（保底可演示），再叠"识别未知香水"动态链路（差异化亮点），与 5.x 开发顺序一致。

### 阶段 2 · QRA2 预警引擎（核心①）｜P0｜约 1.5 天

- **目标**：实现第二章完整流水线，纯函数、零外部依赖、可独立测试。
- **任务**：
  1. Step 1 基线：`AEL = NESIL ÷ SAF`（含 demo 估计值 ×3 惩罚逻辑）；
  2. Step 2 CEL 概率化：五参数分布 + LHS N=10000 固定种子；
  3. Step 3 聚合暴露：`CEL_total = Σ(CEL×w)`；
  4. Step 4 分位判定：P50/P90/P99 + 人群分位策略（健康 P90 / 脆弱 P99）；
  5. Step 5 四道闸门 + `strictest()` 取最严（同级优先级：禁用 > IFRA > 临床 > QRA2）；
  6. Step 6 人群 T_pop 系数 + 交叉反应/生殖毒性附加检查；
  7. Step 7 氧化 D 值模型（Q10 温度加速 + 光照因子）；
  8. 空成分/无数据路径：显式"数据不足"黄灯，绝不静默绿；
  9. 黄金算例测试集（2.5 节全部断言）+ 人群分化实验（五人群 × 全库香水至少存在真实灯色差异）。
- **交付物**：`modules/qra2/`（distributions / engine / oxidation）+ 测试。
- **验收**：黄金算例点估计精确复现（CEL=5.0、比值 20）；固定种子重算逐位一致；pytest 全绿；五人群结果分化实验通过。

### 6.1 设计 token 架构（Tailwind v4 + shadcn/ui 体系）

主题不写死颜色，全部走 CSS 变量两层结构（`src/index.css`）：

```css
:root {                    /* 语义层：光模式 */
  --background: ...;       /* 页面底色 */
  --foreground: ...;       /* 正文 */
  --card / --card-foreground;      /* 卡片 */
  --primary / --primary-foreground; /* 主行动色 */
  --muted / --muted-foreground;    /* 次要信息 */
  --destructive / --border / --ring;
  --radius: 0.625rem;      /* 圆角基准（卡片 10px，柔和高端感） */
}
.dark { /* 暗模式镜像，敏感模式可复用高对比变体 */ }

@theme inline {            /* 映射层：token → Tailwind 工具类 */
  --color-background: var(--background);
  --color-primary: var(--primary);
  --radius-lg: var(--radius);
  /* ... */
}
```

三模式（失嗅/普通/敏感）切换 = 切换一组 token 覆盖（`.mode-anosmia` / `.mode-sensitive` 类），**不是三套页面**。

### 6.2 色彩规范（全站浅场 · 2026-10-05 修订）

初版曾用「实验室（浅）/剧场（暗）」双注册；**2026-10-05 依据用户反馈与《香型HEX色值及对应画面效果.docx》改为全站统一浅场**：显影页与首页/报告页同为瓷白底，显影页的差异性改由主导香型色晕、**组成驱动的飘落粒子**（粒数 ∝ 层权重×香材占比、颜色 = 十二香型 HEX 色谱、形状随香型族：花瓣/叶/水珠/莓果/针叶）、比例分层金字塔与分层液体瓶图承担。

| token | 取值方向 | 用途 |
|---|---|---|
| `--background` | 瓷白 `hsl(210 25% 97%)`（冷调，刻意避开奶油色俗套） | 全站统一底色 |
| `--foreground` | 墨 `hsl(228 18% 11%)` | 正文，对比度 ≥ 4.5:1 |
| `--primary` | 墨底 + 欧莱雅金 `hsl(42 58% 46%)` 点缀（金色 ring/选中/AEL 阈值线） | 主行动与关键强调 |
| 七族光谱 | 花香 `hsl(330 52% 64%)`、柑橘 `hsl(44 78% 58%)`、木质 `hsl(30 36% 50%)`、东方 `hsl(280 32% 52%)`、水生 `hsl(194 48% 56%)`、美食 `hsl(22 52% 56%)`、馥奇 `hsl(96 22% 52%)` | 可视化灵魂；光谱带（七色细线）是贯穿全站的签名元素 |

8. `prefers-reduced-motion` 跟随系统设置。

### 8.2 设计风格调研结论（带来源）

1. **Quiet Luxury（静奢风）**——最贴合欧莱雅调性的主线。[Rise 的分析](https://rise.co/blog/the-quiet-luxury-aesthetic-in-web-design-why-minimalism-converts-better)指出：克制线条、柔和色板、大量留白、毫不费力的字体，反而转化率更高；[Letterhend](https://www.letterhend.com/blog/knowledge/why-do-luxury-brands-choose-minimalist-fonts-the-secret-behind-visual-luxury) 与 [Studio 2AM](https://studio2am.co/blogs/news/elegant-fonts-for-fashion-luxury-and-high-end-branding) 解释了 Chanel/Gucci 式"少即是自信"的字体策略（高对比衬线标题 + 中性无衬线正文）。
2. **Warm Minimalism / "Evening Mode"（2026 主流）**——[UX Design CC 2026 趋势](https://uxdesign.cc/the-most-popular-experience-design-trends-of-2026-3ca85c8a3e3d)：更暖的色调、更慢的过渡、更少的视觉噪音；与我们"象牙白底 + 柔和渐变 + ≤400ms 动效"的规范完全同频。
3. **Liquid Glass（功能性玻璃拟态）**——[Michal Malewicz（Glassmorphism 命名者）2026-27 方向](https://michalmalewicz.medium.com/ui-design-direction-2026-2027-2b4b6eb88336)：玻璃质感回归但服务于功能（层次与聚焦），受 Apple 设计语言影响。**落地口径：仅用于可视化结果卡与悬浮徽章，全局禁用**，避免遮挡信息。
4. **沉浸式 3D / 空间叙事**——[WebMoghuls 2026 趋势](https://www.webmoghuls.com)、[Invoidea](https://invoidea.com) 列为第一趋势（WebGL 瓶身、滚动驱动叙事）。**P2 级**：48h 内不投入，答辩可作叙事愿景。
5. **无障碍设计上游化**——2025-26 行业共识：WCAG 2.2 从"事后补救"变为"设计起点"（[wecreate.digital](https://wecreate.digital)、[Usablenet 美妆电商无障碍](https://blog.usablenet.com)、[Beauty Packaging 包容性趋势](https://www.beautypackaging.com)）。这恰是赛道三的立身命题：**把 A+ 大字号、语音播报、对比度保障做成"看得见的设计语言"而非隐藏选项**——审美与公益主张合流，是本项目最该放大的差异化。
6. **通感可视化的先例支撑**——[IEEE VR 工作](https://ieeevr.org)提出"香水气味可视化为粉色烟雾"式隐喻；[MIT Media Lab 情感化设计研究](https://emotivemodeler.media.mit.edu)论证了感官→视觉的设计综合方法。与 v3 报告引用的 Gilbert 1996 / Spence 2020 形成"学术+工程"双重依据。

### 8.3 「万象 Aura」设计方向定稿：静奢通感（Quiet Luxury × Synesthesia）

- **一句话**：底子是静奢（象牙白、深炭字、黑金行动色、大量留白），灵魂是通感（12 香调 HEX 色板驱动的可视化区是全站唯一的"大胆之处"）。
- **字体**：沿用 aura/web 已自托管的 **Cormorant Garamond**（替代第六章原定的 Playfair Display，避免重复造轮子；两者气质同档）+ **Manrope** 正文；中文栈 `Noto Serif SC` / `PingFang SC` 优雅降级。
- **色彩引擎**：香调可视化色直接采用《香型HEX色值及对应画面效果.docx》的 12 家族色板（柑橘 #FFA500、花果 #FFB6C1、木质 #6B4423、水生 #A1C8D7、东方 #965327、皮革 #4A3628、西普 #706C58、馥奇 #748C67、果香 #D96058、绿叶 #87B36B、美食 #C87941、芳香 #697C57）作为数据资产注入 scentmap 规则库——**设计即数据，数据即设计**。
- **动效**：一次编排好的"结果揭示"（淡入+上移 300ms）+ Canvas 粒子仅在可视化画布内；reduced-motion 全局降级。
- **红线（对照 frontend-design 的 AI 告诉清单）**：不用陶土橘点缀、不做 SaaS 卡片矩阵、不用全大写眉题+中点 meta、按钮不加箭头、可视化区之外零装饰渐变。
